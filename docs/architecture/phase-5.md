# Phase 5 — bounded AI-assisted social draft generation

Base: main 701d490b50ec409857f7569c3068081164519f5a. Phase 5 only; no commit/push or Phase 6. Existing ai.generate explicitly grants Owner, Marketing Admin and Content Creator. Reviewer/Viewer deny. Catalog remains 31; no grant, implication or Brand permission change.

## Trust boundary and deliberate creative limitation

Arbitrary multilingual prose cannot be proven free of all 13 protected commercial claims by keyword matching. This V1 therefore uses a deliberately constrained creative assembly contract: the model selects a language/platform-specific audited neutral hook and a subset/order of server-authorized claim IDs, plus explicitly permitted hashtags. It never supplies accepted free-form captions or claim values. The server assembles and validates the final separate-platform social pack. Unknown prose/keys/IDs are rejected, not “cleaned up.” This sacrifices open-ended copy and bespoke product prose for a defensible boundary. It is not a general semantic factuality/NLP engine. A larger reviewed phrase/typed-fact vocabulary needs a deliberate template/policy change.

The neutral phrase catalog is server-owned, 3 options per platform/language. English, Urdu, Roman Urdu and MIXED are supported; MIXED follows existing ENGLISH_ROMAN_URDU policy. Explicit selected language must be approved; otherwise Brand default applies, or English if no language configuration exists. Approved factual literals remain verbatim: no silent fact translation/transliteration/trimming. No arbitrary user product name, free brief, approved example or CTA is promoted into output/fact authorization. Free creative brief guides only the model’s bounded selection. Output remains an AI-assisted draft requiring human review, never independently verified truth.

## Facts and policies

Use only createBrandService.context(): validated, active/approved filtered, deterministic, 131072-byte bounded projection. Capture its exact revision before network I/O. No table dumps or weaker projection. Revision and prompt version social-safe-assembly-v1 persist with the record.

Structured USER_INPUT facts require category and explicit confirmation. This is provenance, not independent factual proof. EXPLICIT_POST_INPUT permits only those typed input facts. APPROVED_FACT_OR_INPUT also permits a matching approved Brand fact, contact or location index at the captured revision. Unknown/missing/unapproved policy fails closed. EXPLICIT_APPROVAL_REQUIRED remains unavailable: no later approval workflow is invented, and an untrusted checkbox cannot bypass it.

Closed fact grammars further prevent category laundering: PKR numeric price; numeric percent OFF; closed stock states; bounded warranty months; fixed installment count/amount form; capacity with enumerated units or bounded model-code syntax; closed delivery/installation wording. Phone/email/URL require an approved typed Brand contact; address requires an approved Brand location. Unrestricted free-form protected facts, superlative/exclusivity/partnership assertions and unsupported forms reject. No category is interpreted as ALLOWED by absence. All category-prohibited claims in approved category guidance conservatively apply. Contact/location literals preserve approved source text; Owner approval is authority, not proof of real-world truth. No model-created URLs or outbound fetches.

The model can reference an allowed claim but cannot change its value, numeric digits, scope or words. Unknown IDs/extra text/altered facts reject. There is no model authority to grant claims. Hashtags require both approved Brand rules and the closed neutral tag catalog (or independently allowed exact claim value); unknown commercial hashtags reject. BANNED wording is checked over actual rendered strings, including line boundaries; DISCOURAGED remains advisory. Emoji prohibition/intensity is enforced. Counts/length/UTF-8 limits reject without truncation.

## Provider and HTTP

Small AiGenerationProvider interface; OpenRouterGenerationProvider only in production. Native fetch/AbortController; no SDK dependency. Fixed HTTPS https://openrouter.ai/api/v1/chat/completions, redirect:error, bearer only at transport boundary, no arbitrary URL/base-URL/model/routing browser parameters. One explicit request serves exactly selected platforms. Model from existing OPENROUTER_MODEL, key from existing OPENROUTER_API_KEY; optional until generation. No additional environment names. Missing configuration isolates the outage and records safe failure. No paid/default/alternative-model fallback and no automatic retry. Free availability/JSON-schema capability is not guaranteed.

Direct OpenRouter documentation/public model lookup was blocked by the environment proxy (HTTP403). The official @openrouter/sdk 1.4.25 registry tarball was fetched outside the checkout, integrity-verified and inspected, not installed. Its published chatSend, chatrequest, providerpreferences and config contract confirms endpoint, bearer auth, response_format json_schema, require_parameters, allow_fallbacks and data_collection. This is contract-source verification, not a live OpenRouter test. Official SDK default retry behavior is intentionally not adopted.

Provider JSON schema is an optimization; the bounded strict local parser and schema/policy checks remain authoritative. Non-streaming, max_tokens4096, temperature0.2; provider require_parameters:true, allow_fallbacks:false, data_collection:deny. A configured model lacking support fails safely; no silent weaker extraction. Native HTTP error/DNS/TLS/reset/redirect failures are classified safely, upstream bodies never forwarded. Usage is optional and reduced to bounded numeric counts. No tools/function execution, hidden reasoning storage or raw prompt/response logging.

## Resource bounds and transactions

Input 16384 UTF-8 bytes, 2000-code-point brief, 5 unique platforms, 13 unique-category facts; provider payload196608 bytes; provider response65536 bytes; validated output32768 bytes. Body read timeout5s, provider timeout30s. Cancel/disconnect propagates to native fetch/response reader; cancellation cannot guarantee the remote provider stopped billing/processing. No response truncation, arbitrary prose extraction or eval.

MySQL singleton guard serializes short admission/completion mutations across processes. Existing auth_rate_limits gets separate ai_global_day100/rolling24h, ai_actor_day30/rolling24h, ai_actor_minute3/60s scopes. Authentication/media thresholds and cleanup algorithm are unchanged. At most2 active generation leases globally and1 per actor. Lease45s exceeds provider30s budget. No SQL lock spans external I/O. No sleeps/generic deadlock retry/isolation changes.

Lock order: fresh actor/session/canonical catalog -> AI guard -> relevant generation/rate records -> required audit. Anonymous bounded crash reconciliation uses guard -> expired generation -> anonymous audit, never later actor locks. Admission expires at most2 stale leases; expired leases do not authorize completion. Crashed rows can remain physically IN_PROGRESS until a subsequent authorized admission, but expired work does not count toward capacity. Known synchronous success/failure/rejection is persisted terminally; DB/audit outage can prevent persistence, with the durable expiring lease as recovery boundary. No permanent worker or GET-side mutations.

Unique(created_by,request_id) + canonical input digest handles immediate double submit: same input/ID returns the existing attempt, no additional provider call; changed input under that ID rejects. Regenerate uses a new explicit ID/current revision. All browser user controls disable while active, but server enforcement is authoritative. No transaction retry and no silent repeated generation.

## Additional reviewed boundaries

Unicode policy rejects malformed UTF-16, Cc controls (apart from brief/output newline/tab) and invisible Cf format controls except legitimate Urdu ZWNJ/ZWJ. Factual literals disallow Cc entirely. Display text is preserved; banned-word comparison separately removes Cf and applies the existing NFC/case/whitespace comparison, so joiners and rendered line breaks cannot hide banned phrases. No global digit ban: a known stylistic “3 questions” hook is valid, but arbitrary numeric prose is not an accepted output contract.

The OpenRouter adapter also refuses accidental inclusion of its configured API key (raw or JSON-escaped) in message content before calling transport. Browser fixtures explicitly own/reset only the isolated AI rows and AI quota namespaces between invocations, preventing old global quotas/expired leases from creating cross-run interference. Production limits are never reset by tests. All rejected admissions roll back rate writes; no uncontrolled identifiers are admitted past a blocked global gate. Completed records are labelled drafts; failed records are labelled attempts, with no implied generated content.

Provider metadata is supplied by the internal provider descriptor, not hardcoded into generation business logic. The interface exposes a bounded identifier and model; the production factory is OpenRouter only. The initial SQL enum deliberately permits only openrouter; a future separately approved adapter would extend that deployment constraint through a new migration, not rewrite claim/authorization/generation logic.
